# Tensu 前端设计规范

> 适用范围：Tensu 大模型网关平台管理端。技术栈 React + Vite + TypeScript + Ant Design + ECharts。
> 目标：统一视觉与交互语言，打造**年轻、活力、通透、专业不古板**的现代后台体验，兼顾高信息密度与易读性。

---

## 1 设计原则

| 原则     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 内容至上 | 界面为数据与内容服务，减少装饰，让内容自然成为视觉焦点       |
| 清晰精致 | 大量留白、精确对齐、克制配色，追求"少即是多"的精致感         |
| 深度层次 | 通过毛玻璃、柔和阴影与半透明营造轻盈的空间层次，而非硬边框   |
| 一致性   | 同类操作、状态、布局在全平台保持一致，降低学习成本           |
| 即时反馈 | 所有操作有明确、流畅的动效反馈；危险操作二次确认             |
| 无障碍   | 满足对比度、键盘可达、语义化，兼顾深浅色主题与降低透明度偏好 |

---

## 2 品牌与视觉基调

* **产品气质**：精致、克制、优雅、通透——对齐 Apple 设计语言（macOS / iOS HIG），专业而不古板。
* **主色调**：以纯净的浅灰/近白为底，单一优雅的系统蓝为强调色，功能色明快清透。
* **风格关键词**：**极简留白**、**毛玻璃半透明（Vibrancy）**、**连续圆角（Squircle）**、柔和景深、流畅弹性动效。
* **核心手法**：
  * 顶栏、侧栏、弹层等悬浮容器使用**毛玻璃背景模糊**（`backdrop-filter: blur`）+ 半透明；
  * 内容以卡片为容器，圆角大而柔和，接近 iOS 的连续曲率圆角；
  * 弱化边框与分割线，改用留白、层级阴影和材质区分；
  * 交互反馈轻盈流畅，使用弹性/缓动过渡而非生硬切换。

### 3.5 材质与毛玻璃（Materials）

苹果风格的关键：悬浮容器使用半透明 + 背景模糊，营造材质感。

| 材质     | 背景                                                   | 模糊         | 用途                   |
| -------- | ------------------------------------------------------ | ------------ | ---------------------- |
| 顶栏材质 | `rgba(255,255,255,0.72)`（深色 `rgba(30,30,32,0.72)`） | `blur(20px)` | 顶栏、吸顶工具条       |
| 侧栏材质 | `rgba(246,246,248,0.8)`（深色 `rgba(28,28,30,0.8)`）   | `blur(20px)` | 侧边导航               |
| 弹层材质 | `rgba(255,255,255,0.8)`（深色 `rgba(40,40,42,0.8)`）   | `blur(30px)` | 弹窗、抽屉、气泡、菜单 |

* 使用 `backdrop-filter: blur() saturate(180%)` 增强通透质感；
* 需为不支持 `backdrop-filter` 的环境提供不透明降级背景；
* 尊重系统"降低透明度"偏好（`prefers-reduced-transparency`），此时改用不透明背景。

### 3.6 数据可视化色板

采用 Apple 系统色，明快清透，按顺序取用（相邻色区分度高）：

```
#007AFF  #34C759  #FF9500  #AF52DE  #5AC8FA  #FF3B30  #30B0C7  #FF2D55
```

* 单序列趋势：主色渐变（System Blue 半透明填充）；
* 成本类：暖色系（橙→红）；性能/延迟：冷色系（蓝→青）；
* 供应商对比：分类色板固定映射（同一供应商全局同色）。

## 4 字体与排版

### 4.1 字体族

```css
/* 优先使用 Apple 系统字体（SF Pro），跨平台优雅降级 */
font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display",
  "Segoe UI", "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;

/* 数字 / 代码 / Token 用量等 */
font-family-mono: "SF Mono", "JetBrains Mono", ui-monospace, Consolas,
  "Courier New", monospace;
```

* 优先 SF Pro / 苹方（PingFang SC），呈现苹果风格的字形质感；
* 数值、token 数、延迟、request_id、密钥等使用**等宽字体**，保证列表对齐与可读性；
* 大标题可适度加大字号、收紧字距（`letter-spacing: -0.01em`），贴近 SF Pro Display 观感。

## 5 间距与布局

### 5.1 间距基数

以 **4px** 为基础单位：`4 / 8 / 12 / 16 / 24 / 32 / 48`。

* 组件内间距：8~12px；
* 卡片内边距：16~24px；
* 区块间距：24px；
* 页面主内容边距：24px。

### 5.2 圆角与阴影

采用苹果式**连续圆角（Squircle）**与柔和景深，圆角偏大、阴影轻透，营造通透的空间层次。

| 元素          | 圆角 | 阴影                           |
| ------------- | ---- | ------------------------------ |
| 按钮/输入     | 10px | 无（或极轻内阴影）             |
| 标签/徽标     | 8px  | 无                             |
| 卡片          | 18px | `0 4px 16px rgba(0,0,0,0.06)`  |
| 内嵌小卡片    | 12px | `0 1px 6px rgba(0,0,0,0.04)`   |
| 弹窗/抽屉     | 22px | `0 16px 48px rgba(0,0,0,0.18)` |
| 头像/圆形按钮 | 圆形 | 视场景                         |

* 圆角基准 token 设为 **10px**，卡片类容器统一使用 **18px** 大圆角，尽量呈现连续曲率观感；
* 阴影分散、柔和、低透明度，用于替代硬边框；卡片默认不描边或使用极浅分隔线；
* 悬停可交互卡片阴影加深并轻微上浮（如 `0 8px 28px rgba(0,0,0,0.10)` + `translateY(-2px)`），过渡使用缓动。

### 5.3 动效规范

苹果风格强调流畅、有生命力的动效，克制但精致。

* **基础过渡**：`200~280ms`，缓动曲线 `cubic-bezier(0.32, 0.72, 0, 1)`（近似 iOS 弹性缓动）；
* **弹层进出**：抽屉/弹窗使用缩放 + 淡入（`scale(0.96) → 1`，透明度 0 → 1），带轻微弹性；
* **悬停/按压**：卡片上浮、按钮轻微缩放（按压 `scale(0.98)`）；
* **数值/图表**：数字滚动增长、图表入场渐显，避免生硬跳变；
* 尊重 `prefers-reduced-motion`，开启时禁用非必要动效，仅保留淡入淡出。

### 5.3 整体布局

```
┌──────────────────────────────────────────────┐
│  顶栏 Header（Logo · 环境 · 组织切换 · 主题 · 语言 · 用户）
├──────────┬───────────────────────────────────┤
│          │  面包屑 Breadcrumb                  │
│  侧边导航 │ ─────────────────────────────────  │
│  Sider   │                                     │
│ （可折叠）│  内容区 Content（卡片 / 表格 / 图表）│
│          │                                     │
└──────────┴───────────────────────────────────┘
```

* 侧边导航：固定宽度 **240px**，折叠后 **68px**（仅图标）；采用侧栏毛玻璃材质（见 3.5），与内容区通过材质与留白区分而非硬边框；
* 顶栏高度 **56px**，吸顶且使用顶栏毛玻璃材质，滚动时内容自然透出于其后；内容区最大宽度不限制，充分利用横向空间；
* 页面主内容区留白充足（边距 24~32px），主内容区支持栅格 24 列（Ant Design `Row/Col`），响应式断点见第 10 节。

## 7 组件规范

### 7.1 按钮

| 类型    | 用途                      | 样式                 |
| ------- | ------------------------- | -------------------- |
| Primary | 页面主操作（每屏 ≤ 1 个） | 主色实心             |
| Default | 次操作                    | 描边                 |
| Text    | 表格行内操作、弱操作      | 无边框               |
| Danger  | 删除、吊销、重置          | 危险色，且需二次确认 |

* 加载中按钮显示 loading 图标并禁用；
* 危险操作统一使用 `Popconfirm` 或 `Modal.confirm` 二次确认。

### 7.2 表格（核心组件）

* 默认分页 20 条，支持 `10/20/50/100`；
* 列对齐：文本左对齐，数值/token/成本**右对齐**并等宽字体；
* 支持列筛选、排序、列显隐配置、密度切换；
* 长列表使用服务端分页 + 后端排序，禁止一次性加载全量；
* 行操作固定在最右列，超过 3 个操作收进「更多」下拉；
* 空状态使用统一 `Empty` 插画 + 引导操作；
* 表格整体置于圆角卡片容器内（16px 圆角），表头无重边框，行分隔使用极浅次级边框或斑马底色，风格轻盈。

### 7.3 表单

* 采用**垂直标签**布局（label 在上），复杂配置分步或折叠；
* 必填项标红星，校验即时反馈；
* 密钥类输入默认掩码，提供「显示 / 复制」按钮；
* 危险/不可逆配置项加醒目说明（`Alert` 或 tooltip）。

### 7.4 状态标签（Tag / Badge）

| 状态      | 颜色   | 示例       |
| --------- | ------ | ---------- |
| 在线/健康 | 成功绿 | `● 健康`   |
| 降级/限流 | 警告橙 | `● 限流中` |
| 故障/离线 | 危险红 | `● 故障`   |
| 处理中    | 紫     | `● 重试中` |
| 未知/停用 | 中性灰 | `● 停用`   |

* 状态一律使用「圆点 + 文案」组合，不单独依赖颜色（无障碍）。

### 7.5 统计卡片

* 采用 16px 圆角卡片，柔和阴影，内边距充足（20~24px）；
* 结构：标题 + 大数值 + 环比/同比（带升降箭头与颜色）+ 迷你趋势图（sparkline）；
* 数值使用等宽字体，超大数字千分位分隔；
* 成本类展示币种符号，token 类展示单位（K/M）；
* 可点击的卡片支持悬停上浮与阴影加深反馈。

### 7.6 反馈组件

| 场景               | 组件                               |
| ------------------ | ---------------------------------- |
| 轻量成功/失败提示  | `message`                          |
| 需要用户注意的通知 | `notification`                     |
| 二次确认           | `Modal.confirm` / `Popconfirm`     |
| 页面级错误         | `Result` 组件                      |
| 加载               | `Skeleton`（首屏）/ `Spin`（局部） |

## 8 数据可视化规范

* 图表库：**ECharts**（`echarts-for-react`）；
* 统一封装图表主题（浅色 / 深色两套），复用第 3.5 节色板；
* 折线图用于趋势（用量、成本、延迟），柱状图用于对比（模型/供应商），饼图/环形图用于占比（费用分布）；
* 时间轴统一格式，支持时间粒度切换（分/时/天/周/月）；
* 所有图表提供 tooltip、图例可点选、空数据占位；
* 关键阈值（如配额线、P99 目标）用虚线标注；
* 大数据量图表启用采样 / 懒加载，避免卡顿。

## 11 主题与深色模式

平台提供**浅色（Light）**与**深色（Dark）**两套完整主题，均遵循苹果风格的材质与配色。

* 使用 Ant Design v5 **ConfigProvider + theme token** 实现，深色主题基于 `theme.darkAlgorithm` 定制；
* 提供浅色、深色、**跟随系统**（`prefers-color-scheme`）三种模式，用户偏好持久化到本地；
* 所有自定义颜色通过 CSS 变量 / token 定义，禁止硬编码颜色值；
* 主题切换实时生效并带平滑过渡（背景/文本颜色过渡 ~200ms）；
* 图表、代码块、毛玻璃材质、状态色在两套主题下均需单独校验对比度；
* 两套主题的材质取值见 3.5，中性色见 3.3 / 3.4，功能色见 3.2。

### 11.1 浅色主题 token（示例）

```ts
import { theme } from 'antd';

export const lightTheme = {
  algorithm: theme.defaultAlgorithm,
  token: {
    colorPrimary:   '#007AFF',
    colorSuccess:   '#34C759',
    colorWarning:   '#FF9500',
    colorError:     '#FF3B30',
    colorInfo:      '#5AC8FA',
    colorBgLayout:  '#F2F2F7', // 页面背景
    colorBgContainer: '#FFFFFF', // 卡片背景
    colorText:      '#1C1C1E',
    colorTextSecondary: 'rgba(60,60,67,0.6)',
    colorBorderSecondary: 'rgba(60,60,67,0.12)',
    borderRadius:   10,
    borderRadiusLG: 18,
    fontSize:       14,
    wireframe:      false,
  },
};
```

### 11.2 深色主题 token（示例）

```ts
export const darkTheme = {
  algorithm: theme.darkAlgorithm,
  token: {
    colorPrimary:   '#0A84FF',
    colorSuccess:   '#30D158',
    colorWarning:   '#FF9F0A',
    colorError:     '#FF453A',
    colorInfo:      '#64D2FF',
    colorBgLayout:  '#000000', // 页面背景
    colorBgContainer: '#1C1C1E', // 一级卡片
    colorText:      '#FFFFFF',
    colorTextSecondary: 'rgba(235,235,245,0.6)',
    colorBorderSecondary: 'rgba(84,84,88,0.36)',
    borderRadius:   10,
    borderRadiusLG: 18,
    fontSize:       14,
    wireframe:      false,
  },
};
```

### 11.3 切换实现要点

* 顶栏提供主题切换入口（浅色 / 深色 / 跟随系统）；
* 跟随系统时监听 `window.matchMedia('(prefers-color-scheme: dark)')` 变化实时响应；
* ECharts 维护浅/深两套图表主题，随全局主题联动切换；
* 毛玻璃材质、阴影、图片/插画在深色下使用各自的深色取值，避免直接反相。

---

## 12 国际化（i18n）

* 首期支持**简体中文（zh-CN）**与**英文（en-US）**，默认跟随浏览器语言，可手动切换并持久化；
* 使用 `react-i18next`，文案统一走 key，禁止在组件中硬编码可见文案；
* Ant Design 组件通过 `ConfigProvider locale` 同步语言；
* 日期时间、数字、货币使用 `Intl` / dayjs 本地化格式；
* 文案 key 命名：`模块.子模块.含义`，如 `provider.form.apiKeyRequired`；
* 预留多语言扩展（新增语言只需补充语言包）。

---

## 13 无障碍（A11y）

* 正文文本对比度 ≥ 4.5:1，大字号 ≥ 3:1；
* 状态不单独依赖颜色（配图标 / 文案）；
* 所有交互元素键盘可达，焦点态明显（focus ring）；
* 表单控件关联 `label`，图标按钮提供 `aria-label`；
* 弹窗打开时焦点锁定，关闭后焦点回归触发元素。

## 14 前端工程约定

### 14.1 目录结构（建议）

```
frontend/
├── src/
│   ├── api/            # 接口封装（按模块）
│   ├── components/     # 通用组件
│   ├── features/       # 业务模块（providers/models/audit/...）
│   ├── layouts/        # 布局（主框架、空白页）
│   ├── hooks/          # 自定义 hooks
│   ├── locales/        # i18n 语言包（zh-CN / en-US）
│   ├── stores/         # 全局状态
│   ├── theme/          # 主题 token 与图表主题
│   ├── utils/          # 工具函数（格式化、请求、鉴权）
│   ├── routes/         # 路由配置
│   └── main.tsx
├── index.html
└── vite.config.ts
```

### 14.2 编码约定

* 组件化开发，单个组件职责单一；容器组件与展示组件分离；
* 统一请求层：拦截器处理鉴权头（JWT）、统一错误码映射（对应 PRD 5.1.2）、request_id 透传；
* 统一格式化工具：token 数（K/M）、成本（币种）、延迟（ms/s）、时间（相对/绝对）；
* 状态管理轻量化（Zustand / Context），避免过度封装；
* 命名：组件 PascalCase，hooks 以 `use` 开头，常量 UPPER_SNAKE_CASE。

### 14.3 交互细节约定

* 列表加载使用骨架屏，避免布局跳动；
* 表格/图表数据刷新提供手动刷新按钮与可选自动刷新（如监控页）；
* 长耗时操作（拉取模型列表、健康检查）显示进度或后台执行提示；
* 复制类操作（密钥、request_id）统一提供一键复制 + toast 反馈；
* 危险操作、批量操作明确告知影响范围。
